## The core idea: context, notes, history, environment

<div lang="zh-CN">

模型当前能看到的工作上下文，与任务持续存在的状态，是两回事。实验路径把有限的工作窗口、可维护的笔记、可回查的历史和独立延续的环境连接起来。

公开的 [`new_context` 工具定义](https://github.com/openai/codex/blob/6af345407d9c2a568da9d01b6c4b81a9e61495c0/codex-rs/core/src/tools/handlers/new_context_window_spec.rs#L9) 与[处理器](https://github.com/openai/codex/blob/6af345407d9c2a568da9d01b6c4b81a9e61495c0/codex-rs/core/src/tools/handlers/new_context_window.rs#L14)显示，这条路径请求一次不生成摘要的换窗，并保留环境。旧消息不会因此全部继续出现在活跃上下文中；需要时，通过笔记和历史工具找回线索或原始证据。

课程用“观察预算 → 保存线索 → 切换窗口 → 回查证据 → 继续并验证”组织学习。这是教学选取的工作流，不是强制执行顺序；写什么笔记、何时检索，仍取决于模型行为。

</div>

## Seven steps from intuition to practice

<div lang="zh-CN">

1. **桌面与档案**：点击四种状态，预测换窗后什么还在、什么需要恢复。
2. **从摘要到回查**：比较滚动摘要、摘要链和 Codex 实验的恢复路径。
3. **跟着一次切窗**：播放六步因果流程，观察预算、窗口和 fallback 分支。
4. **给未来的便签**：在有限模拟容量中保留目标、约束、证据出处和下一步。
5. **找回那条证据**：尝试字面查询、角色过滤和索引延迟，再按消息 ID 阅读。
6. **边界与故障**：改变实验入口条件，区分过时笔记、空结果和当前验证。
7. **重建与迁移**：重排恢复流程，把设计迁移到依赖升级场景并复述原理。

每课有可检查的答题或操作条件。浏览页面不计入掌握进度，自由复述不会被关键词或长度自动判为“学会”。

</div>

## What context compaction does—and what remains uncertain

<div lang="zh-CN">

从[公开 history / notes 接口](https://github.com/openai/codex/blob/6af345407d9c2a568da9d01b6c4b81a9e61495c0/codex-rs/ext/history-notes/src/tools.rs#L24)可以确认：笔记使用后端虚拟路径；历史支持窗口和消息列举、按 ID 读取，以及区分大小写的字面子串搜索。接口还说明了写入读取与列举、搜索之间的一致性差异。

这些材料没有公开完整的后端数据库、训练方法，也没有证明性能提升。课程把“源码事实”“设计解读”和“教学模拟”分别标出。窗口预算、便签容量、消息、代码版本和 PASS / FAIL 都是合成例子。

实验的可用性还受起始模型能力、账号、配置和后端等条件影响。详见[官方模型说明](https://learn.chatgpt.com/docs/models#experimental-context-management)、[配置参考](https://learn.chatgpt.com/docs/config-file/config-reference)与[固定版本的激活条件](https://github.com/openai/codex/blob/6af345407d9c2a568da9d01b6c4b81a9e61495c0/codex-rs/core/src/session/token_budget.rs#L21)。课程只模拟这些条件，不会改变你的 Codex 配置。

</div>
