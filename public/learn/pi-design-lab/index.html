00 / THE BIG PICTURE

Pi 的设计，
是一组有理由的取舍。

为什么不随时删掉旧 Tool Result？为什么摘要要能读？为什么保存了聊天还不足以恢复工作？跟随一次任务，把五份资料连成一个因果模型。

图中任务是教学虚构。文件、模型输入、Provider 的缓存和执行状态有各自的职责；一次“继续”会穿过这些边界。

01

保存在哪里，决定能否带走。

本地有可读记录，才能检查与交接；缓存命中只说明过去的计算可能被复用。

02

03

记下做到了哪里，才能安全恢复。

“模型想调用工具”与“工具结果已可靠保存”之间，还有外部效果发生但结果未知的时间窗口。

本课对作者思想的归纳：让长时间工作既负担得起，又有可以接手的历史和可以恢复的执行。每个局部选择，都在这几个目标之间权衡。这个归纳不是作者逐字原话。缓存原文 ↗
阅读路线与前置概念

先知道：token 是模型处理的单位，context 是这次请求可用的输入，tool 是宿主程序执行的函数。01–03 建立计算和上下文模型，04–06 解释所有权与运行时，07 用真实结构检验，08 无提示复述并迁移。章节内的“先预测”答错会指出要回看的机制；阅读进度不会自动算作理解。

示意循环

Tool Call 属于 assistant 消息；Tool Result 由宿主执行后产生。结果被加入历史，再交给模型判断下一步。循环次数不是固定的。

把镜头推进模型：Prefill 与 Decode

KV 是计算状态

K 是注意力匹配使用的向量，V 是按注意力权重汇合的信息向量；这里省略层、头和矩阵维度。KV 不是保存事实的 key-value 字典。原文机制 ↗

类比：上次已整理的笔记，可以接着用；类比哪里会失效？

缓存像已经处理好的前缀笔记，但它既不是人类可读的摘要，也不是永久记忆。模型、token 序列和存留条件改变时，这份数值状态可能不能复用。Decode 仍要生成新的输出；cache hit 不等于复用上次完整答案，也不会减少这次逻辑上下文的长度。

02 / THE PREFIX IS THE UNIT

同一个 Session，
不保证同一个前缀。

先改变一个条件，再播放比较。观察第一个不匹配的位置：它后面的内容即使原样保留，也可能必须重新计算。

对应 Prompt Caching In Agents逻辑分段，不是真实 tokenizer

前缀实验台

先选变化，再播放
这模拟可用性，不猜测 Provider 内部原因。

绿色“可复用”是这个简化模型下的上界，不是命中率预测。真实服务还受最小缓存长度、分块、TTL 与 API 策略影响；Session ID 只可能帮助寻找前缀。

作者的取舍：不要把所有旧 token 都当成浪费。稳定追加可保留缓存，也保留决策用过的工具证据；上下文压力足够大时，再接受一次有损重写。S1 ↗
边界：延迟加载工具只有在模型原生支持、且变化纯追加时才有这条路径。删工具、重排 schema、改 prompt 仍可能改变前部输入。
再深入：删短 Prompt，什么时候才回本？

用自定的成本单位比较“中间重写一次”与“以后每轮少读一点”。下面不是任何 Provider 的现价，也不是 Pi 的账单。

增量重算成本 ≈ 后部保留 token × (1 − 读价比)；每轮节省 ≈ 删去 token × 读价比。未计摘要生成、缓存写入、重新 token 化和信息损失；实际收益需要测量。

历史仍然有来处。

本例窗口 C = 128,000；默认 reserve = 16,384；默认 keepRecent = 20,000。近期预算是近似 token 目标，切点还需服从消息边界，不代表固定 20 条消息。S6 规则 ↗

七步看清一次压缩

手动演示压缩路径

每个 T 组假设为 4,000 token，包含完整的 User / Assistant call / Result，便于看预算怎样移动保留起点；这不是实际分词或完整切点算法。即使自动阈值未达到，也可以手动演示。摘要请求单独构建，但仍要提供待总结的旧历史。

版本对照：文章说“turn 结束后”，现在还是这样吗？

文章解释（S2）：在 turn 结束后检查自动压缩，context overflow 时可在中途压缩。
2026-09-07 固定版文档（S6）：工具批次完成、结果追加且还要继续响应时，也会在下一次 assistant 请求前检查；新用户 prompt 前与底层 run 结束后同样有检查。工具批次终止 run 且无排队消息时跳过该续跑检查。
稳定的原则是“在安全边界决定下一份 context”；不要把某篇文章的时机描述写成永远不变的 API 保证。

切点练习：一个很长的 turn，能从哪里保留？

输入顺序：User → Assistant(tool call) → Tool Result → Assistant(tool call) → Tool Result。尝试选一个保留起点。

先选择一个切点。

常规切点优先尊重 turn；超长 turn 可在 assistant 边界拆分，另做 turn-prefix 摘要。Tool Result 不能脱离其 Tool Call 成为切点。重复压缩时还要带入上一摘要及先前保留下来、现在变旧的内容。

分支摘要 ≠ 压缩摘要。
前者把离开分支的经验带到目标路径；后者缩小当前路径的上下文。二者都可以是可读文本，但触发与用途不同。S6 ↗
Session ID、Leaf、Lane：三个容易混淆的词

Session ID 标识一份会话；leaf 是树上当前位置；Lane 是运行时绑定到路径的工作通道。一个 Session 可以存多条分支；历史 v2 的多个 Lane 可以并行推进各自的 leaf。一个 JSONL 里出现分叉，只证明历史有分支，不能据此认定有多个 Lane 在并发运行。

故障注入：从哪里恢复？

当前规范的简化状态机
不确定窗口不能靠猜。没有结果，不表示效果没有发生。never 的未知效果应形成中断结果；safe 的重放也可能重复计算或计费。这不构成外部效果 exactly-once 保证。

本页的计数只用于说明本地状态机。没有模拟真实文件写入、进程崩溃或 Provider。S7 §0.4–0.6 ↗

恢复、取消与 UI 重连，为何要分开？

当前规范中，accept 先可靠记录操作，drive 才推进效果；重新附着先读取状态，不自动替你执行未知工作。UI 断开后可以重建快照；一次调用的取消信号，也不自动等于持久业务取消。历史 v2 的状态图可用 Idle → Running → Suspended → Resume 辅助理解，但当前 durable operation state 比四个界面状态更细。

Events 用于观察，Hooks 可以拦截或改变工作。Hook 自己发出的外部请求在提交前可能重复，需要由其实现处理幂等性。把事件广播当成持久日志、把“显示完成”当成已落盘，都会混淆职责。

实现边界：v2 文档已合并，不等于所有设计都已完成

当前 harness.md §0.9 明列了尚未实现或尚未闭合的项目，例如 watchSession、JSONL snapshot compaction、部分 telemetry/search/fork 行为。本课静态检查了恢复入口和相应设计段落，没有运行 Pi 的恢复测试，更没有用旧 v3 Session 数据证明新运行时的可靠性。
